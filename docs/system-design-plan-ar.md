# خطة نظام إدارة تجارة وشحن السيارات

## 1. القرار المعماري

- مشروع جديد نظيف، وليس ترقية مباشرة لمشروع `copart` القديم.
- نعيد استخدام قواعد العمل المفيدة من Copart: السيارات، التجار، المبيعات، المشتريات، الصندوق، المحاسبة ودفتر الحسابات.
- نعتمد أسلوب واجهة BidAdmin: قائمة جانبية قابلة للطي، صفحات بسيطة، بطاقات إحصائية، جداول موحدة، دعم RTL والوضع الداكن.
- تطبيق واحد Monolith باستخدام Laravel + Inertia + React لتقليل التعقيد والتكلفة.

## 2. التقنية المقترحة

- Backend: Laravel 13، PHP 8.3 أو أحدث ضمن نطاق الدعم.
- Frontend: React 19.3 + TypeScript + Inertia.
- UI: Tailwind CSS 4، Radix UI، Lucide Icons، Recharts.
- Database: PostgreSQL 17 للإنتاج، وSQLite للاختبارات المحلية فقط.
- Authentication: Laravel Sanctum، مع صلاحيات Roles/Permissions.
- Files: تخزين مرفقات وفواتير وصور السيارات على S3-compatible storage.
- Background jobs: Laravel Queue + Redis للـ imports والتقارير والتنبيهات.
- Tests: PHPUnit + Playwright لمسارات العمل الأساسية.

## 4. الشاشات

### الرئيسية

- عدد السيارات حسب الحالة: مشتراة، بالميناء، داخل حاوية، بالنقل البري، وصلت، مباعة.
- إجمالي المشتريات والمبيعات والمصاريف والربح.
- الحاويات المفتوحة والمتأخرة.
- النقلات البرية المفتوحة والغرامات غير المسددة.
- أرصدة التجار والصندوق والبنوك.
- آخر العمليات والتنبيهات.

### السيارات

- رقم السيارة الداخلي، VIN، Lot، الماركة، الموديل، السنة، اللون.
- التاجر/المالك، سعر الشراء، العملة، تاريخ الشراء، المزاد، المورد.
- الحاوية، النقلة البرية، حالة السيارة وموقعها.
- مصاريف مباشرة، حصة الحاوية، حصة النقل، الغرامات، التكلفة النهائية.
- سعر البيع، المبلغ المقبوض، الرصيد، الربح.
- صور ومستندات وملاحظات وسجل تغييرات.

### المشتريات

- فاتورة شراء قد تحتوي سيارة واحدة أو عدة سيارات.
- المورد/المزاد، العملة، سعر الصرف، الإجمالي، المدفوع، المتبقي.
- عند اعتماد الفاتورة ينشأ قيد محاسبي تلقائياً.

### المبيعات

- اختيار سيارة متاحة، اختيار العميل/التاجر، سعر البيع، الخصم والدفعات.
- منع بيع السيارة مرتين.
- احتساب الربح من التكلفة النهائية المعتمدة.
- فاتورة PDF وسند قبض وقيد محاسبي تلقائي.

### التجار

- بيانات التاجر والاتصال.
- كشف حساب موحد: سيارات، دفعات، مصاريف، غرامات، أرصدة.
- يمكن أن تكون سيارات الحاوية كلها لتاجر واحد أو كل سيارة لتاجر مختلف.

### الحاويات

- رقم الحاوية، BL No، الوكيل/شركة الشحن، ARF No، التاريخ والحالة.
- من 1 إلى 4 سيارات فقط داخل الحاوية.
- مصاريف مستخرجة من Excel: أجور الوكيل، MIP، demurrage، المخزن، العمولة، الجمارك، وأي بند إضافي.
- دفعات الحاوية والرصيد المتبقي.
- زر اعتماد التوزيع مع معاينة حصة كل سيارة قبل الحفظ.

### النقل البري

- رقم الرحلة، الناقلة/رقم اللوحة، اسم السائق، الهاتف، تاريخ التحميل والوصول.
- حمولة من 1 إلى 6 سيارات فقط.
- أجرة النقل، الغرامة، مصاريف إضافية، المدفوع والمتبقي.
- توزيع الأجرة والغرامة تلقائياً على السيارات المحملة.

### المصاريف والغرامات

- مصروف مباشر على سيارة.
- مصروف مشترك على حاوية.
- مصروف مشترك على نقلة برية.
- غرامة سيارة مستقلة.
- كل مصروف يحمل: النوع، التاريخ، الوصف، العملة، المبلغ، المستفيد، المرفق، حالة الدفع.

### المحاسبة ودفتر الحسابات

- دليل حسابات مزدوج القيد.
- قيود يومية تلقائية للشراء والبيع والقبض والصرف والمصاريف والغرامات.
- يومية عامة، أستاذ عام، ميزان مراجعة، صندوق وبنوك، ذمم التجار والموردين.
- دفتر حساب لكل تاجر ولكل سيارة وحاوية ونقلة.
- لا يسمح بتعديل قيد مرحّل؛ يتم العكس بقيد تصحيح للحفاظ على الأثر التدقيقي.

## 5. قواعد توزيع التكاليف

### حاوية

- القاعدة الافتراضية الأبسط: توزيع متساوٍ على السيارات الفعالة داخل الحاوية.
- حصة السيارة = مجموع مصاريف الحاوية ÷ عدد السيارات.
- خيار مستقبلي: توزيع بنسبة ثابتة أو وزن/حجم، لكن لا يدخل في النسخة الأولى.
- فرق التقريب يوضع على آخر سيارة حتى يساوي مجموع الحصص مجموع المصروف تماماً.
- عند إضافة/حذف سيارة أو تعديل مصروف قبل الاعتماد يعاد الحساب تلقائياً.
- بعد الاعتماد تقفل الحصص؛ أي تعديل لاحق ينشئ نسخة توزيع جديدة مع سجل تدقيق.

### نقل بري

- حصة السيارة = (أجرة النقل + الغرامة المشتركة + المصاريف الإضافية) ÷ عدد السيارات المحملة.
- الغرامة الخاصة بسيارة لا توزع، بل تحمل على السيارة مباشرة.
- نفس قاعدة فرق التقريب والقفل بعد الاعتماد.

### مثال

- حاوية فيها 4 سيارات ومصاريفها 4,000: حصة كل سيارة 1,000.
- نقلة فيها 6 سيارات، أجرتها 1,200 وغرامتها المشتركة 300: حصة كل سيارة 250.
- إذا كانت على سيارة غرامة خاصة 50، تصبح تكلفة تلك السيارة الإضافية 300 وليس 250.

## 7. حالات العمل

### السيارة

مسودة ← مشتراة ← بانتظار الشحن ← داخل حاوية ← وصلت الميناء ← بالنقل البري ← وصلت المخزن ← متاحة للبيع ← مباعة ← مسلمة.

### الحاوية

مسودة ← تحميل ← مشحونة ← وصلت ← مفرغة ← مغلقة.

### النقلة البرية

مسودة ← محملة ← بالطريق ← وصلت ← مغلقة.

### القيد المالي

مسودة ← مرحّل، أو مرحّل ← معكوس. لا يوجد حذف نهائي لعملية مالية مرحّلة.

## 8. استيراد Excel

الملف الحالي يحتوي ورقة واحدة باسم `OTOMOBİL` و253 صفاً، وحقوله الرئيسية:

- التسلسل، التاريخ، الوكيل، BL، رقم الحاوية، ARF.
- Agent، MIP، Demurrage، Depot، Commission، Customs expense.
- المدفوع والإجمالي/الرصيد التراكمي.

تنفذ شاشة الاستيراد كالتالي:

1. رفع الملف ومعاينة أولية.
2. مطابقة الأعمدة مع حقول النظام.
3. تمييز صفوف الحاويات عن صفوف القبض والمصروفات العامة.
4. كشف التكرار بواسطة رقم الحاوية + BL + التاريخ.
5. عرض الأخطاء قبل الاعتماد.
6. استيراد على دفعة واحدة قابلة للتراجع قبل الترحيل المحاسبي.

## 9. التصميم البصري

- RTL افتراضي مع عربي وإنجليزي وكردي.
- قائمة جانبية بعرض 220px قابلة للطي مثل BidAdmin.
- رأس صفحة صغير: عنوان، وصف مختصر، وأزرار الإجراء الرئيسية فقط.
- الجداول موحدة: بحث، فلاتر، ترتيب، pagination، تصدير Excel/PDF.
- الألوان محايدة، ولون شركة واحد قابل للتغيير من الإعدادات.
- الأخضر للمدفوع/المكتمل، البرتقالي للجزئي، الأحمر للمتأخر أو الغرامة.
- الهاتف يعرض بطاقات بدلاً من جداول عريضة.

## 10. الصلاحيات

- مدير النظام: كل شيء.
- محاسب: القيود، الصندوق، الدفعات والتقارير المالية.
- مبيعات: العملاء، البيع والتحصيل دون تعديل تكلفة الشراء.
- مشتريات: الموردون، الشراء والسيارات.
- لوجستيات: الحاويات والنقل والحالات والمرفقات.
- مشاهدة فقط: التقارير والكشوف دون تعديل.

كل إضافة وتعديل وحذف وعكس قيد يسجل في `activity_logs` مع المستخدم والوقت والقيم القديمة والجديدة.

## 11. التقارير الأساسية

- تكلفة وربح كل سيارة.
- كشف حساب تاجر.
- سيارات كل حاوية وتوزيع مصاريفها.
- سيارات كل نقلة وتوزيع أجرتها وغرامتها.
- الحاويات المتأخرة وDemurrage.
- المشتريات والمبيعات حسب الفترة والتاجر.
- المقبوضات والمدفوعات والأرصدة.
- اليومية العامة، الأستاذ، ميزان المراجعة، الأرباح والخسائر.

### المرحلة 4 — المحاسبة (أسبوعان إلى ثلاثة)

### المرحلة 5 — التثبيت (أسبوعان)

التقدير الإجمالي لنسخة أولى مستقرة: 10–11 أسبوعاً لفريق صغير، مع إبقاء النطاق كما هو وعدم إضافة ميزات جانبية أثناء التنفيذ.

## 13. معايير القبول الحرجة

- لا تقبل الحاوية أكثر من 4 سيارات، ولا النقلة أكثر من 6.
- يمكن أن تكون كل السيارات لتاجر واحد أو لتجار مختلفين.
- مجموع حصص السيارات يساوي المصروف المشترك تماماً بعد التقريب.
- تغيير عدد السيارات قبل الاعتماد يعيد التوزيع فوراً.
- التكلفة النهائية للسيارة قابلة للتتبع إلى كل بند مصدر.
- كل عملية مالية تنتج قيداً متوازناً: إجمالي المدين = إجمالي الدائن.
- لا يمكن حذف أو تعديل قيد مرحّل أو بيع سيارة مباعة.
- جميع العمليات الحرجة مغطاة باختبارات آلية وسجل تدقيق.

## 14. ما لا يدخل في النسخة الأولى

- تطبيق موبايل مستقل.
- GPS مباشر للناقلات.
- تكامل آلي مع المزادات أو الجمارك.
- توزيع تكاليف حسب الوزن/الحجم.
- ذكاء اصطناعي أو تنبؤات مالية.

هذه العناصر تؤجل حتى يثبت سير العمل الأساسي ويستخدم فعلياً.
